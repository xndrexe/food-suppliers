# Поиск поставщиков продуктов питания

Прототип: https://xndrexe.github.io/food-suppliers/

Закупщик кафе или магазина выбирает категорию («рыба и морепродукты»,
«упаковка для доставки») и город и получает не выдачу поисковика, а список
поставщиков, у которых сайт уже прочитан: минимальный заказ, цена, доставка,
регион работы, документы, контакты. Список отсортирован по тому, с кем
связаться первым, и у каждого поставщика видно, за что он поднялся, чего не
хватает и что спросить при звонке. Отмеченные поставщики идут в план обзвона
со статусом и заметкой, их можно сравнить таблицей и выгрузить в Excel.

## Почему такой формат

Поставщиков закупщик ищет в Яндексе и тратит время не на поиск, а на
чтение: открыть десяток сайтов, найти условия опта, понять, возят ли в его
город и есть ли документы, и только потом звонить. Половина выдачи — доски
объявлений и справочники. Сервис берёт на себя именно эту часть.

- **Сбор отдельно от интерфейса.** Сборщик ходит в поиск и на сайты по
  расписанию, интерфейс читает готовую базу. Страница открывается мгновенно,
  не зависит от лимитов поисковика и модели и работает даже с телефона.
- **Ничего не выдумываем.** Языковая модель отвечает за каждое условие
  дословной цитатой с сайта. Цитаты на сайте нет — условие не показывается,
  вместо него вопрос на звонок. Цитату видно в карточке.
- **Оценка открытая.** Баллы складываются из понятных признаков (свой город
  или доставка в него, производитель, контакты, ИНН, документы, известные
  цена и мин. заказ), и закупщик видит, за что поставщик стоит выше.
  «Рейтингу 87» без объяснения он не поверит — и будет прав.
- **Решение, а не справочник.** «Что спросить при звонке», мой список со
  статусами и заметками, сравнение и выгрузка — это работа закупщика после
  поиска, она тоже в сервисе.

## Как работает сборщик

```
поиск Яндекса (категория × город)
  → отсев досок объявлений, справочников, маркетплейсов
  → сайт: главная + до 3 страниц «контакты», «доставка», «опт», «документы»
  → правила: телефоны, почта, ИНН (с проверкой контрольной суммы), упоминания документов
  → модель: тип компании, ассортимент, мин. заказ, цена, доставка, регионы, документы
  → сверка цитат с текстом сайта: не нашлась — поле удаляется
  → оценка, плюсы и минусы, вопросы на звонок
  → docs/data.js
```

| Файл | Что делает |
|---|---|
| `collector/search.py` | Yandex Search API, список агрегаторов |
| `collector/fetch.py` | загрузка сайта и выбор нужных подстраниц |
| `collector/extract.py` | правила, запрос к модели, сверка цитат |
| `collector/score.py` | баллы, плюсы и минусы, вопросы на звонок |
| `collector/run.py` | весь проход, кэш, запись базы |
| `docs/` | интерфейс: HTML, CSS и JS без сборки и зависимостей |

## Запуск

Интерфейс — открыть `docs/index.html` в браузере.

Сборщик (Python 3.10+, без внешних библиотек):

```
export YANDEX_SEARCH_KEY=...  YANDEX_FOLDER_ID=...
export LLM_BASE_URL=https://.../v1  LLM_API_KEY=...  LLM_MODEL=...
python -m collector.run                         # все категории и города из config.json
python -m collector.run --only "Рис для суши" --city Москва
```

Модель — любая с OpenAI-совместимым API (для Yandex AI Studio ещё
`LLM_AUTH=Api-Key` и `LLM_PROJECT=<каталог>`). Категории, запросы и города —
в `config.json`. Повторный запуск берёт сайты и ответы модели из
`data/cache`.

Тесты: `python -m pytest -q`
